# Athlete profile and recovery evidence
The optional secondary first-login wizard records sport preferences, weekly days, time per session, preferred days, training experience and goal mode. Explicitly save the profile through the owner-only endpoint. Sport availability and training rhythm still use existing canonical forms. No personal records are seeded. The profile is stored on the server, not in browser cache. The secondary-only migration must be applied before enabling that deployment; no primary data migration is required for this increment.
The Garmin Personal API key is still installed by the administrator as a private Edge secret; the wizard links to the official key setup and checks import status. No self-service key storage or scheduler activation is implied.
Cycle permission defaults to false. Only the authenticated confirmed owner may grant it or explicitly request the capability check. The check uses the documented Personal API summary endpoint, returns a limited status, and does not store raw cycle data or map unverified phase codes. No automatic cycle ingestion, medical claim or phase-specific training rule. Revoke consent by saving the profile with the option off.
Morning recovery uses up to 90 calendar days when provided by the owner snapshot GET. The earlier reference excludes the latest 14 days, requires ten measurements, and repeated low HRV uses actual distinct measured dates. No new clinical threshold or training clearance. The existing scheduling rules and server-side workout validation remain unchanged in this increment. The athlete-profile planner integration, fully self-service Garmin key installation and consent-gated cycle history/learning remain separate acceptance work. No real athlete or credential fixtures.

# GARMIN_AI UX principles

- KISS: one primary task per screen; default to a useful concise summary.
- Show the next action before retrospective analyses. Use progressive disclosure for supporting evidence.
- Never hide safety warnings, current errors, personal approval or calendar state behind optional detail.
- Reuse Garmin and existing Coach data; no duplicate entry or second data model for a different screen.
- Existing navigation is unchanged by this first Coach-focused UX pass.
- Dashboard/Coach: today's decision, reason, interaction, upcoming plan.
- Calendar: scheduled and completed sessions, approval and publication.
- Training/analysis: actual session and longitudinal evidence.
- Goals: targets and progress toward them.
- Race Prep: concrete event preparation and recovery.
- Future Coach knowledge/research: web-backed sources when useful, private data minimized; no external lookup or model integration in this UX pass.
- Validate responsive layout, focus navigation, regression tests and production build before release.
